# 🚀 Автоматическое развёртывание и тюнинг Zabbix 7.0 LTS для промышленной эксплуатации

[English](README.md) | **Русский**

Автоматизированные, полностью идемпотентные Bash-скрипты для развёртывания и тонкой настройки **Zabbix 7.0 LTS** на **Ubuntu 22.04 / 24.04 LTS** с **PostgreSQL**, **TimescaleDB**, **Nginx** и **PHP-FPM**.

Предназначены для быстрого развёртывания самостоятельных высокопроизводительных узлов мониторинга в защищённых внутренних сетях.

---

## 📌 Возможности

* **100% идемпотентность и отказоустойчивость**: скрипт можно запускать и перезапускать в любой момент. Если он прервался, просто запустите его снова — он обнаружит уже созданные базы данных, схемы, сертификаты и учётные данные без потери данных и без дублирования настроек.
* **Интеграция с TimescaleDB и автотюнинг**:
  * Подключает официальный репозиторий TimescaleDB и устанавливает расширение для нужной версии PostgreSQL (PG 14 на 22.04, PG 16 на 24.04).
  * Настраивает PostgreSQL под железо через `timescaledb-tune` (shared buffers, work memory, рабочие процессы).
  * Создаёт гипертаблицы TimescaleDB и включает автоматическое сжатие для истории, трендов и журнала аудита.
* **Настройка без участия человека**: автоматически создаёт `/etc/zabbix/web/zabbix.conf.php` с правильными правами. **Мастер настройки в браузере проходить не нужно!**
* **Самовосстанавливающаяся настройка репозитория**: определяет кодовое имя ОС по `/etc/os-release` и удаляет устаревшие или неподходящие источники apt и пакеты release для Zabbix.
* **Безопасность из коробки**:
  * Генерирует самоподписанные TLS-сертификаты (при повторных запусках используются существующие).
  * Включает HTTPS с перенаправлением с HTTP и TLS 1.2 / 1.3.
  * Настраивает локальную аутентификацию через сокет с `scram-sha-256` (порты базы данных не открыты в сеть).
  * Настраивает межсетевой экран UFW (`22`, `80`, `443`, `10051`).
  * Сохраняет сгенерированные учётные данные БД с ограниченными правами (`chmod 600`) в `/root/.zabbix_deploy_credentials`.
* **Тюнинг производительности и ОС**: отдельный скрипт `zabbix_tuning.sh` оптимизирует внутренние поллеры, трапперы и кэши Zabbix, а также параметры ядра Linux (`vm.overcommit_memory`, `fs.file-max`, сетевые сокеты) для **100–300+ хостов**.

## 📋 Системные требования

* **ОС**: Ubuntu 22.04 LTS (Jammy) или 24.04 LTS (Noble)
* **Права**: root или `sudo`
* **Нужные порты**: `80` (HTTP), `443` (HTTPS), `10051` (Zabbix Trapper/Server), `22` (SSH)

| Версия Ubuntu | Версия Zabbix | PostgreSQL | TimescaleDB | PHP-FPM |
| :--- | :--- | :--- | :--- | :--- |
| **Ubuntu 22.04 LTS** | 7.0 LTS | 14 | timescaledb-2-postgresql-14 | 8.1 |
| **Ubuntu 24.04 LTS** | 7.0 LTS | 16 | timescaledb-2-postgresql-16 | 8.3 |

## 🛠️ Быстрый старт

### 1. Клонирование и развёртывание

```bash
git clone https://github.com/V1p3rL0rd/zabbix-automated-deployment
cd zabbix-automated-deployment
chmod +x zabbix_deploy.sh zabbix_tuning.sh
sudo ./zabbix_deploy.sh
```

#### Необязательные параметры:
| Параметр | Описание | По умолчанию |
| :--- | :--- | :--- |
| `-d, --domain <fqdn>` | `server_name` в Nginx / CN TLS-сертификата | `hostname -f` |
| `-t, --timezone <tz>` | Часовой пояс PHP | `Europe/Moscow` |
| `-e, --email <email>` | Email для TLS-сертификата | — |
| `-h, --help` | Показать справку | — |

### 2. Доступ к веб-интерфейсу
Откройте в браузере `https://<IP-сервера>/` (или ваш домен).
Веб-конфигурация создаётся скриптом автоматически, поэтому сразу откроется экран входа.

* **Логин по умолчанию**: `Admin`
* **Пароль по умолчанию**: `zabbix`

> ⚠️ **Важно**: сразу смените пароль администратора в *User settings → Profile*!

Учётные данные PostgreSQL и сведения о развёртывании хранятся в:
```bash
sudo cat /root/.zabbix_deploy_credentials
```

### 3. (Необязательно) Тюнинг производительности и ядра

Запустите скрипт тюнинга для настройки поллеров, размеров кэшей и параметров ядра sysctl:
```bash
sudo ./zabbix_tuning.sh
```

## ✅ Проверка состояния

Убедитесь, что все службы мониторинга и бэкенда запущены:
```bash
systemctl is-active postgresql nginx php*-fpm zabbix-server zabbix-agent2
```
Все службы должны вернуть `active`.

Проверка гипертаблиц TimescaleDB:
```bash
sudo -u postgres psql -d zabbix -c "SELECT hypertable_name FROM timescaledb_information.hypertables;"
```

Журнал развёртывания:
```bash
tail -n 50 /var/log/zabbix-deploy.log
```

## 🧰 Идемпотентность и восстановление

Если во время развёртывания случился сетевой тайм-аут или сервер перезагрузился:
1. Запустите `sudo ./zabbix_deploy.sh` снова.
2. Скрипт:
   * Возьмёт ранее сгенерированный пароль БД из `/root/.zabbix_deploy_credentials`.
   * Пропустит создание базы данных, если она уже существует.
   * Пропустит импорт схемы, если таблицы уже заполнены.
   * Использует существующие TLS-сертификаты из `/etc/ssl/zabbix/`.
   * Проверит, что службы правильно настроены и запущены.
